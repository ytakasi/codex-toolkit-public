## Codex Toolkit Rules

- 会話、ドキュメント、コメント、スキル本文、運用メモは日本語を基本にする。コマンド名、オプション名、JSONキー、保存値、外部API契約のような機械可読な値は安定させる。
- 作業開始時は、議論、ローカル編集、統合作業のどれに近いかを軽く見立て、完了境界や正本が曖昧なら先に整理する。
- ユーザーが「編集しないで」「レビューだけ」と言った時は、ファイルを編集せず、指摘、選択肢、次の行動に留める。
- 新規リポジトリ / 空リポジトリ / 初回実装では、初期骨格、正本ドキュメント、`docs/DEVELOPMENT_STORY.md`、最初の検証方法を先に揃える。見送る時は理由を確認する。
- リポジトリの `AGENTS.md` にはリポジトリ固有差分と toolkit 管理ブロックだけを置き、共通方針を手で重複させない。
- 指定された作業ディレクトリ、worktree、ブランチ、成果物の範囲を作業空間の正本として扱い、別 worktree や兄弟ブランチの状態を前提にしない。
- 正本、生成物、外部追跡物を分ける。`codex-kit` 管理リポジトリでは `agent-skills/repo` がリポジトリ正本、`.agents` が生成ランタイム、`.codex/hooks.json` が管理対象フック入口。
- スキル、エージェント、フックを新規作成・更新する時は、先に `skill-authoring` スキルを使って正本ルートを判定する。`codex-kit` 管理リポジトリでは `.agents` は生成ランタイムなので直接編集しない。
- 実装を含む作業では設計判断と検証結果を長期記録へ残し、検証欄には実行したコマンドと実際の結果だけを書く。未実行、失敗、サンドボックス / ツール環境起因は分けて報告する。
- 削除、ブランチ / worktree 整理、デプロイ、マイグレーション、DB、秘密情報、環境変数、外部書き込みは、影響範囲、未保存変更、未push状態、再実行性を先に確認する。
- ユーザー向け表示文言を変える時は、表示ラベルと識別子、保存値、外部契約を分け、互換性を壊さない。
- ツールチェーン確認では PATH 上にあることと実際に起動できることを分ける。CIや自動化は必要最小対象と実行OSを先に確認する。
- サブエージェント、カスタムエージェント、作業レーンを使う時は、親エージェント、サブエージェント、未完了の委譲を分ける。渡す入力は作業対象、固定制約、出力範囲、完了条件へ絞る。
- 専門ワークフローは、このリポジトリの `.agents/skills` に該当スキル / プロファイルが配備されている時だけ使う。存在しないスキル名を前提にせず、必要なら代替手順を短く説明する。
- 議論や実装が一区切りついたら、必要に応じて `project-retrospective` スキルで再利用できるスキル、テンプレート、運用ガイダンス、ワークフロー候補を短く振り返り、汎用化できるものはリポジトリ固有事情を剥がして toolkit 昇格候補にする。
- 別セッションへ持ち越す時は、短い `NEXT_SESSION` 系ドキュメントに現在地、再現コマンド、検証結果、次にやること、未解決論点、参照ファイルを残す。
